# Claws 1.0.6

Claws 1.0.6 packages the reviewed feature expansion and reliability fixes previously published as 1.0.0 Beta. The version now follows 1.0.5 so GitHub and version-aware tools can identify it as the newest standard release. No feature or data-format rollback is involved; this is a version and packaging update of the approved beta source.

## Features

- Paste up to 500 independent links, with three lookups at a time, per-row retry and explicit Download confirmation.
- Source-driven video resolutions up to 8K, with Compatible or Original output. Original preserves the source streams without intentional re-encoding; editor compatibility depends on their codecs and container.
- Download captions as TXT, timestamped TXT, SRT or VTT without downloading media. This uses source captions, not speech recognition.
- Preview download size and temporary disk-space requirements, distinguish failed estimates from unknown sizes, and retry failed estimates without resetting successful results.
- Preserve single-link choices and completed estimates across navigation. Refresh invalidates estimates when dimensions, entries or durations change.
- Copy finished files through Windows native drag handles, with long/UNC path handling and a dedicated OLE worker. A stalled receiver does not own the window thread; one blocked drag worker can prevent further drags until it returns or Claws restarts.
- Bundle all four Salted Flutters Polaris font weights with integrity and glyph-spacing safeguards. No separate font installation is required.

## Reliability and performance

- Recover older queues conservatively, including empty backup snapshots, with durable recovery-consumption records and preserved corrupt bytes.
- Keep startup recovery retryable if a retained-subtitle Library record cannot be saved. Try Again finishes publication bookkeeping without downloading again.
- Bind workspace manifests to their verified roots, publish without replacing existing files, and delete Library media only through identity-verified file handles. Legacy entries without ownership evidence support Library-only removal and Show in folder.
- Journal destructive Library operations and persist history before updating memory. Retained subtitle files have persistent Library/Queue actions and bounded repair from known output roots.
- Bound tool download sizes and network deadlines; prepare installs in unique staging folders and hold the engine writer only for final replacement.
- Keep Processing authoritative despite delayed transfer output. Run disk sampling and reservation operations on blocking workers with checked arithmetic.
- Use a shared processing policy for commands and space estimates. Fast Save skips optional metadata, embedded subtitles and MP3/M4A cover art; necessary conversion, merging and container repair remain.
- Enforce the twelve-language subtitle limit without silently truncating selections, exclude live chat from transcript-track counts, and refresh track names and kinds correctly.
- Make confirmation decisions final on first activation, deduplicate status notices, support keyboard radio navigation and retain stable Library tiles.

## Installation and compatibility

Use `Claws_1.0.6_x64-setup.exe`. The installer retains the existing Windows installation policy, including explicitly allowing installation over higher-numbered versions. The application identifier and data location remain `dev.claws.downloader`; the build does not delete existing settings, history, queues or caches. Installer policy/configuration verification does not substitute for a live upgrade test.

Queue schema remains 3 regardless of the application version number. Old Claws 1.0.5 cannot execute schema-3 jobs; returning to this build can recover one unambiguous queue it preserved. New Library ownership fields have defaults for older entries.

Windows 11 and WebView2 are required. Releases are unsigned. yt-dlp is installed separately on first launch; ffmpeg is needed for merging/conversion and some caption formats. YouTube extraction may require Deno or Node.js.

## Validation and limits

Validation passed on 2026-11-09: 409 Rust tests; 241 Node tests (7 font, 19 queue, 152 logic, 63 motion); 2 Python font tests; feature-enabled Clippy with warnings denied; production frontend build; clean-export `npm ci` and production build; native optimized release/NSIS build; and `git diff --check`. The new kept-file recovery test was observed failing before the fix and passing afterward. Source tests use temporary data and generated media; they do not prove all-site compatibility.

Real-source low-speed diagnosis remains evidence-blocked: no affected URL/format has been supplied. No Internet throughput improvement is claimed. Audio disk-space estimates remain conservative assumptions, not exact measured peaks for every codec/backend. Explorer/editor import, a deliberately stalled receiver, Windows 10, and clean installation/upgrade on disposable Windows profiles remain manual acceptance work. The owner's installed application and data are not used as test fixtures.
