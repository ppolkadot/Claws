# Claws 1.0.7

Fixes a Windows download-completion failure affecting filenames and folders containing accented, Japanese or stylized Unicode characters.

## Fix

Windows yt-dlp could save a file correctly but print its finished path using a legacy code page, dropping or corrupting characters despite the Python UTF-8 environment settings. Claws then could not find that reported path and displayed “yt-dlp reported a finished file outside the download's work folder.”

Production yt-dlp calls now explicitly request `--encoding utf-8`. The file ownership and canonicalization checks remain intact. A regression runs the real Windows executable through production command setup and arguments, verifies the exact Unicode path, and publishes an existing completed file from a disposable work folder without contacting a live site.

## Updating

Install `Claws_1.0.7_x64-setup.exe`, then use **Try Again** on affected failed jobs. Their completed files are retained in their work folders. Existing downloads can be reused by yt-dlp; removing or cancelling the job can discard that retained work.

Application identifier `dev.claws.downloader`, settings/history locations and queue schema 3 are unchanged. No feature rollback is involved. No user data was used as a mutable test fixture.

## Validation and limits

Fresh validation: 410 Rust tests, including the real-tool Unicode regression; feature-enabled Clippy with warnings denied; production frontend build and bundled-font checks; optimized Windows NSIS build; installer archive and executable-payload verification. The Unicode failure was reproduced before the correction and the corrected path and publication were verified afterward.

The installer remains unsigned. Live installation/upgrade and editor-drag acceptance remain unverified. This correction does not claim improved network download speed. Earlier releases and their installer/checksum records remain unchanged.
